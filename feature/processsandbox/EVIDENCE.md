# Process Sandbox evidence record

Status: reviewed

Research reviewed on 2026-10-18. This detector observes the **sampling thread of the current SDK host**, through one at-most-64-KiB `/proc/thread-self/status` read and the same thread's public UID API. It adds no native unit, process, permission, privileged operation, network request or host signing policy. It does not enumerate other processes or persist raw status text, TIDs or UIDs in the presentation/export. Different observations from the same status snapshot are correlated views, not independent attestations.

## Signals

### Matched-thread credential views

- Observable signal: The kernel status `Uid` real, effective, saved and filesystem quartet, compared with `Process.myUid()` sampled before and after the bounded status read.
- Producing subsystem: The Android Common Kernel procfs task credential formatter and `thread-self` symlink, plus Android's public process UID API; AOSP Zygote establishes the ordinary application credential baseline.
- Mechanism: ACK `fs/proc/thread_self.c` resolves `thread-self` to the **calling task's** `tgid/task/tid`; ACK `fs/proc/array.c` emits the four credentials in the proc reader's user namespace. The entire host/status/host sequence is synchronous inside one IO coroutine without suspension, so the UID API and proc snapshot refer to the sampling thread. AOSP Zygote `SpecializeCommon` sets the real/effective/saved IDs to the chosen application UID. The data layer rejects nondecimal, out-of-uint32, duplicate and incorrectly sized UID fields. If the public UID differs before and after the read, the host baseline becomes IDENTITY_CHANGED with no UID/capability warning.
- References: Android Developers [Process.myUid](https://developer.android.com/reference/android/os/Process#myUid()), [FIRST_APPLICATION_UID](https://developer.android.com/reference/android/os/Process#FIRST_APPLICATION_UID), [LAST_APPLICATION_UID](https://developer.android.com/reference/android/os/Process#LAST_APPLICATION_UID); ACK [android14-6.1 fs/proc/thread_self.c](https://android.googlesource.com/kernel/common/+/refs/heads/android14-6.1/fs/proc/thread_self.c), [android14-5.15 fs/proc/array.c](https://android.googlesource.com/kernel/common/+/refs/heads/android14-5.15/fs/proc/array.c#183), and reviewed ACK [android14-6.1 fs/proc/array.c](https://android.googlesource.com/kernel/common/+/refs/heads/android14-6.1/fs/proc/array.c#188); AOSP [Android 10 Zygote.cpp setresuid](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-10.0.0_r1/core/jni/com_android_internal_os_Zygote.cpp#1039) and [Android 16 Zygote.cpp](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r1/core/jni/com_android_internal_os_Zygote.cpp#2025); AOSP [multiuser.cpp](https://android.googlesource.com/platform/system/core/+/refs/tags/android-10.0.0_r1/libcutils/multiuser.cpp#24) implements appId modulo AID_USER_OFFSET; its [android_filesystem_config.h](https://android.googlesource.com/platform/system/core/+/refs/tags/android-10.0.0_r1/libcutils/include/private/android_filesystem_config.h) defines the multiuser offset.
- Applicability: Android 10+ on all four supported ABIs, with readable `thread-self/status`. The AOSP ordinary-app comparison applies only when `uid % 100000` is in 10000..19999 and the SDK host is neither FLAG_SYSTEM nor FLAG_UPDATED_SYSTEM_APP. Root/system/Bluetooth/network-stack, isolated, SDK-sandbox and other special identities are outside this baseline, even in another user. Public [ApplicationInfo flags](https://developer.android.com/reference/android/content/pm/ApplicationInfo#FLAG_SYSTEM) exclude preinstalled/updated system hosts; no hidden privileged flag or reflection is used. OEM/system hosts are observed contextually.
- Visibility limits: Only the sampling task is inspected. There is no claim about the main thread, all threads, other processes, other users, or whole-device identity. Native libraries may intentionally change per-thread real/effective/saved/filesystem IDs; a difference is a local diagnostic inconsistency with the ordinary application baseline, not proof of hooking, a root family or compromise. The before/after guard cannot detect changes away and back inside the read. A modified kernel/framework/procfs or UID API may forge matching views, and this is not independent verification.
- Result states: OBSERVED matching/differing quartet; IDENTITY_CHANGED; MISSING; MALFORMED; UNAVAILABLE; PERMISSION_DENIED; FAILED; NOT_EVALUATED. A missing/inaccessible proc path is UNAVAILABLE, not a zero credential. `FileInputStream` cannot distinguish all missing-path and denied-path errors, so FileNotFoundException is deliberately ambiguous UNAVAILABLE rather than guessed absent or permission-denied.
- Interpretation: Only stable ordinary application hosts with an observed quartet differing from the same thread's API UID yield WARNING. Matching credentials, special hosts and normal snapshots are INFO/CONTEXT, never an all-clear security guarantee. Missing/denied/changing identity is INFO/SUPPORT; malformed/read-failed evidence is INFO/ERROR. Typed details preserve partial failures alongside an independently observed warning.

### Granted capability masks

- Observable signal: `CapEff`, `CapPrm` and `CapAmb`, parsed separately as unsigned hexadecimal masks of at most 64 bits, including bit 63 without signed overflow.
- Producing subsystem: ACK task credentials and procfs `task_cap`; AOSP Zygote `CalculateCapabilities`/`SetCapabilities` defines the ordinary application startup comparison and legitimate special-host exceptions.
- Mechanism: Read all three masks from the same bounded status snapshot. AOSP grants Bluetooth/network-stack identities explicit capabilities, and child Zygotes SETUID/SETGID/SETPCAP; those special hosts are outside the ordinary application scope. AOSP additionally grants **CAP_BLOCK_SUSPEND, bit 36**, to processes in the wakelock GID, so this bit is conservatively excluded from scoring in every granted set, without assuming the wakelock GID is absent. Nonzero remaining effective, permitted or ambient masks are reported as expanded grants for an eligible ordinary host. The bounding set, inheritable set and NoNewPrivs are not collected or scored.
- References: ACK [android14-5.15 fs/proc/array.c task_cap](https://android.googlesource.com/kernel/common/+/refs/heads/android14-5.15/fs/proc/array.c#308), [android14-6.1 fs/proc/array.c](https://android.googlesource.com/kernel/common/+/refs/heads/android14-6.1/fs/proc/array.c#308); ACK [android15-6.6 capability.h CAP_BLOCK_SUSPEND](https://android.googlesource.com/kernel/common/+/refs/heads/android15-6.6/include/uapi/linux/capability.h#370); AOSP [Android 10 CalculateCapabilities](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-10.0.0_r1/core/jni/com_android_internal_os_Zygote.cpp#1156) and [Android 16 CalculateCapabilities](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r1/core/jni/com_android_internal_os_Zygote.cpp#2219), with SetCapabilities at Android 10 line 1085 and Android 16 line 2129.
- Applicability: All supported ABIs; same stable ordinary installed-app scope and readable matched-thread proc status as the UID observation. System/updated-system apps and nonordinary identities remain context-only. Missing capability fields are a coverage limitation rather than an empty set. A custom privileged SDK host may intentionally retain extra grants and must interpret them in its own policy.
- Visibility limits: Granted sets describe the sampled task in its kernel/user-namespace context. A numeric capability does not establish that an attempted privileged operation would succeed under SELinux, namespaces or a specific target object. No privileged operation is attempted. Custom firmware or an intentionally changed ordinary host can legitimately differ from the AOSP baseline; the result does not attribute the reason. Kernel/proc manipulation can hide or fabricate masks. The three masks share a source and are not presented as independent root detections.
- Result states: OBSERVED unsigned masks including zero; MISSING; MALFORMED; UNAVAILABLE; PERMISSION_DENIED; FAILED; NOT_EVALUATED. Malformed/overflowing/signed/duplicate tokens never become zero. A missing host classification or changing sampled UID suppresses baseline warnings.
- Interpretation: Only an eligible ordinary application with an observed grant outside the bit-36 exception yields WARNING, phrased as a baseline difference. Zero masks and bit 36 alone are INFO/CONTEXT. System/special hosts are INFO/CONTEXT even with extra grants. Missing/denied evidence is INFO/SUPPORT and malformed/read failures INFO/ERROR. A nonzero **CapBnd** or NoNewPrivs=0 has no influence on this detector.

### Sampling-thread Seccomp mode

- Observable signal: The decimal `Seccomp` mode in the same matched-thread status snapshot: 0 disabled, 1 strict or 2 filter. Other nonnegative integers are retained as unknown future modes.
- Producing subsystem: ACK seccomp task state and conditional procfs formatting; AOSP Zygote chooses whether to install the application/system filter.
- Mechanism: Parse one decimal integer without executing a restricted syscall or modifying seccomp state. ACK emits the field only under CONFIG_SECCOMP. AOSP `SetUpSeccompFilter` explicitly skips installation when `gIsSecurityEnforced` is false. Consequently mode 0 is an observation, not a root verdict. Mode 2 says a filter mode is active and does not inspect the BPF program or establish the policy's completeness.
- References: ACK [android14-5.15 fs/proc/array.c task_seccomp](https://android.googlesource.com/kernel/common/+/refs/heads/android14-5.15/fs/proc/array.c#330), [android14-6.1 seccomp.h modes](https://android.googlesource.com/kernel/common/+/refs/heads/android14-6.1/include/uapi/linux/seccomp.h#10); AOSP [Android 10 SetUpSeccompFilter](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-10.0.0_r1/core/jni/com_android_internal_os_Zygote.cpp#518), [Android 16 SetUpSeccompFilter](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r1/core/jni/com_android_internal_os_Zygote.cpp#639).
- Applicability: All supported ABIs and Android 10+, subject to actual kernel configuration and proc visibility. The mode is not compared against an assumed invariant across OEM, debug, permissive or custom builds. No architecture-dependent syscall probe is introduced.
- Visibility limits: Only the sampled worker task is observed, not all threads or processes. A missing field can reflect kernel configuration or a modified interface. A present filter does not prove AOSP policy contents, resistance to bypass or complete syscall protection. NoNewPrivs is intentionally not interpreted as evidence that a filter must exist.
- Result states: OBSERVED mode 0/1/2; OBSERVED unknown numeric mode with unsupported interpretation; MISSING; MALFORMED; UNAVAILABLE; PERMISSION_DENIED; FAILED; NOT_EVALUATED.
- Interpretation: Every known mode, including 0, is INFO/CONTEXT. The mode-0 row states that filtering is disabled for the sampled task and explains the legitimate AOSP permissive-policy path. Unknown/missing/denied modes are INFO/SUPPORT; malformed/read failures INFO/ERROR. Seccomp never raises this detector's severity.

## Failure handling and validation

All raw input stays in the data layer. One stream read is capped at 65536 bytes plus one overflow sentinel, closes with `use`, checks cancellation between chunks, and does not retry. The IO repository checks cancellation before and after collection; CancellationException propagates instead of becoming an error report. No exception messages enter reports; failures retain only stable `FailureName` strings. Field-level parser errors preserve independently valid fields, and no unsupported read becomes a zero mask or a disabled Seccomp mode.

The JVM tests cover clean contextual observations; each UID slot; multiuser and special/system identities; the wakelock exception; high unsigned bits and each granted set; missing/malformed/duplicate/overflowing tokens; all Seccomp modes and unknown modes; bounded reads; single-snapshot collection; read failure and denial; changing UID; cancellation; Chinese wording; and UID-free exports. Full Gradle/ABI/SDK/lint execution is delegated to GitHub CI because this workspace has no Android SDK. JVM results do not validate actual procfs visibility, per-thread credential behavior, OEM startup policy or modified kernels. Physical-device checks remain required on stock and intentionally modified Android 10 through current devices, multiple users, preinstalled/system SDK hosts and all four ABIs; no physical-device validation has been performed here.
